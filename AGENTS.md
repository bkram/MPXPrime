# Agent Instructions

This file is the single source of truth for AI coding agents (Claude Code, Codex, etc.) working in this repo. `CLAUDE.md` is a symlink to this file.

## Project

Native macOS FM composite (MPX) generator — real-time broadcast-style stereo encoder with RDS, "MPX Prime Studio". Swift 6 / SwiftUI / AVAudioEngine, SPM package rooted at `macOS/`. Targets macOS 15+. Two executable targets: `MPXPrime` (the encoder, ships as "MPX Prime Studio.app", **universal**) and `MPXPrimeMeter` (the companion receive/analyze app "MPX Prime Meter.app" — captures an MPX composite from an audio device or an in-process RTL-SDR / SDRplay tuner and decodes stereo + RDS in a SwiftUI dashboard; **Apple-Silicon-only**, because it statically links the arm64-only RTL-SDR tuner — see below); they share `MPXPrimeCore` (DSP) and `MPXPrimeUI` (Canvas SwiftUI components), and both ship in the same DMG. The Meter's WAV recorder lives in a small pure-Foundation `MPXPrimeRecording` library target (`CanonicalWavWriter` + `MeterRecorder`) so the recording path is unit-testable (`MeterRecorderTests`) -- the executable target itself can't be imported by tests. The recorder's 0.45 robustness contract (pinned by tests): NaN packs as silence / Inf clamps (never `Int32(_:)`-trap), the writer stops CLEANLY at the RIFF 4 GiB limit (64-bit counter, frame-aligned finalize), the header is patched every ~2 s so an interrupted capture stays readable, `failureReason` surfaces disk-full / limit / misuse to the UI (the view model polls it each tick and stops the recording with a message), and finalization runs OFF the caller thread because `finish()` blocks on a filesystem flush while the analysis thread takes `recordLock` per block. For the same reason the Meter's measurement engine (`MeterAnalysis` + `MeteringPrimitives`: linear-phase FIR measurement filter, DC tracker, 50 ms peak-hold slot windows, SM.1268-5 >77 kHz exceedance statistic, uniform sliding 60 s BS.412 window with max-over-placements, coherent RDS subcarrier level meter reading the PEAK deviation of the shaped subcarrier -- the injection level encoders set; an RMS-equivalent detector reads ~24% low on real biphase, see `encoderRoundTripReadsTheSetInjection`; `PilotRDSPhaseMeter` for the EN 50067 sec 1.2 pilot-to-RDS subcarrier phase -- two IDENTICAL lock-in chains off one 19 kHz NCO, which is what makes the reading immune to the capture clock's pilot-frequency offset, so do NOT "simplify" it to reuse `PilotPLL` or to give the two paths different filters; MAX/AVE/MIN + a 1 kHz-bin deviation histogram off the same slot ring; an optional monitor-ballistics deviation readout (`MonitorDeviationMeter`, 0.5 ms integrating detector on the same measurement path -- the display convention of hardware modulation monitors, shown alongside and never feeding the SM.1268 statistics); carrier offset; baseband noise as the exact FIR complement (`delayed - filtered`) feeding a 0..4 signal-quality scale; stereo balance) lives in `MPXPrimeCore` and is covered by the deterministic `MeterAnalysisTests` (synthesized composites with exactly-known deviation -> exact expected readings). Do not degrade these measurement semantics without re-checking ITU-R SM.1268-5 / BS.412-9 / EN 50067; the tests encode the standards. Since 0.45 every readout also carries a VALIDITY flag and the UI shows `--` rather than a number it cannot justify (`peakValid`, `devScaleValid` -- the pilot-referenced scale needs the same pilot-presence threshold the PILOT readout uses, held ~0.4 s; `exceedanceValid` only after 60 s with `exceedanceBoundPct` published before that; `pilotRDSPhaseValid` needs one averaging time constant AND a fast-vs-slow drift gate, because the coherence primes at exactly 1.0 and is scale-free; `stereoCorrelationValid` on a mean-removed, level-gated coefficient; `qualityValid`; a balance expiry). Adding a readout means adding its validity gate; never publish a scale-derived kHz figure without `devScaleValid`. The Meter links `CMPXTuner` — the vendored RTL-SDR / SDRplay -> FM-demod -> MPX tuner (repo-root `tuner/`, GPL-3.0) compiled as a C++ library with a pure-C ABI (`mpx_tuner_capi.h`), decoding the dongle **in-process** (no subprocess, no FIFO; it keeps a CAPTURE rate separate from the DEMOD rate -- the FM chain always runs at 250/256 kHz behind a `ComplexDecimator`, so the operator-selectable IQ rate widens only the RF-spectrum span and can never move an MPX measurement; at factor 1 the RTL path must keep its original packed-uint8 `processSplit` call, whose normalization LUT and raw-byte saturation detection the complex path does not reproduce; that saturation share is exported via `mpxtuner_iq_overload()` and drives the Meter's RF OVERLOAD badge through `RFOverloadGate` -- a railing front end inflates every level-derived reading, measured 2026-08-31); the tuner CMake also builds `mpx-offline`, the device-free bench harness that replays recorded or synthesized IQ through the identical demod wiring (see tuner/README.md); it links Homebrew `librtlsdr` + `liquid-dsp`, and when the SDRplay API SDK is present at build (`/Library/SDRplayAPI/`, gated by `FM_TUNER_HAS_SDRPLAY` in `Package.swift`) it also builds the SDRplay RSP backend (the SDRplay runtime library is dlopened, never linked, so a build without the SDK just omits SDRplay and falls back to RTL-SDR). Build the x86_64 release slice with `--product MPXPrime` so the Meter/CMPXTuner are skipped on Intel. Swift deps are `swift-atomics` and `hummingbird` (2.x; the remote-control REST server, both platforms). **Linux CLI port (milestone 1)**: the same Package.swift builds the encoder on Linux via manifest-level `#if os(Linux)` — Linux-side targets are `MPXPrime` + `MPXPrimeCore` + `MPXPrimeNative` + `MPXPrimeRecording` + `MPXPrimeAcceleration` (Accelerate/os shim: same-name vDSP/vvtanhf implementations + `OSAllocatedUnfairLock` polyfill; compiles EMPTY on macOS so macOS numerics are bit-identical by construction — pinned by `AccelerateShimTests`' golden fixture, regenerate with `MPXPRIME_CAPTURE_GOLDEN=1` on macOS) + `CAlsa` (libasound system library) with `ALSAAudioEngine.swift` replacing `AudioOutputEngine.swift`. GUI/Meter/tuner targets are macOS-only. Linux pins its own strict baseline (`verifier_baselines/default-linux-x86_64.json` — captured with the shim's SIMD numerics: SIMD8 dotpr/conv + Cephes-style vectorized tanh, all SSE2-safe (NO AVX flags — small x86 CPUs lack it); changing shim numerics requires a Linux recapture); `default.json` stays macOS. Convention for platform-conditional code: `#if canImport(Accelerate) import Accelerate #else import MPXPrimeAcceleration #endif` (same shape for Darwin/Glibc and os), whole-file `#if os(macOS)` wraps for GUI/CoreAudio files (never manifest `exclude:` lists), and zero call-site diffs in DSP code. Any change to the shim or Linux-compiled DSP requires re-running `--verify --baseline-strict` on macOS UNCHANGED (zero-drift gate) and recapturing the Linux baseline if Linux numerics moved.

- Primary entrypoint: `macOS/Package.swift`
- Default user config: `~/Library/Application Support/MPX Prime Studio/MPX Prime Studio.ini`
- **Platform tiers: Apple Silicon (arm64) is Tier 1** (primary, fully-supported, optimization target). **Intel (x86_64) is Tier 2, best-effort** — ships in the universal binary with an identical audio chain, but perf work targets arm64 first; give Intel lighter-weight fallbacks where cheap (e.g. the arch-tiered GUI refresh profile), don't block on Intel-only optimization. **Linux x86_64 is Tier 3, experimental CLI-only** — the encoder builds and runs headless (`--nogui` into ALSA, all `--verify*`, `--bench`; no GUI, no Meter, no SDR); correctness-first, perf work deferred until production Linux hardware exists. See docs/BUILDING.md "Linux (CLI-only)".

See also: `docs/manual.md` (MPX Prime Studio user manual: usage / configuration / RDS / reference tables), `docs/manual-meter.md` (MPX Prime Meter user manual: SDR/audio input, readouts, recording, calibration), `docs/ARCHITECTURE.md` (detailed DSP chain and stage descriptions), `docs/BUILDING.md` (build / run / test / package from source), `plan.md` (roadmap). The two user manuals are split per app; the shared RDS PI/ECC + PTY reference tables live in `docs/manual.md`'s appendices and the Meter manual links to them.

## Commands

```bash
# Build (debug / release)
swift build --package-path macOS
swift build --package-path macOS -c release

# Run
swift run --package-path macOS MPXPrime              # GUI
swift run --package-path macOS MPXPrime --nogui      # headless
swift run --package-path macOS MPXPrime --config "/path/to/MPX Prime Studio.ini"
swift run --package-path macOS MPXPrime --nogui --control-port 8737  # headless + REST API/dashboard

# Offline verification (no audio devices touched)
swift run --package-path macOS MPXPrime --verify --seconds 5
swift run --package-path macOS MPXPrime --verify-presets --seconds 5
swift run --package-path macOS MPXPrime --verify-long --seconds 30
swift run --package-path macOS MPXPrime --verify-receiver --seconds 5  # coherent receiver-side decode (separation @ 1/10/14 kHz, pilot, RDS); 0.36 adds guard-band cancellation depth + pilot/RDS phase-lock drift gate
swift run --package-path macOS MPXPrime --verify-multiband-coupling --seconds 2  # A/B experimental multiband inter-band coupling toggle
swift run --package-path macOS MPXPrime --verify-advanced-dynamics --seconds 4  # A/B experimental single-stage Advanced Dynamics leveler vs AGC+multiband
swift run --package-path macOS MPXPrime --verify-ssb-stereo --seconds 4  # A/B experimental SSB Stereo encoder (SSB-leaning stereo encoding) (sidebands + decode separation)
swift run --package-path macOS MPXPrime --verify-hf-transients --seconds 5  # hi-hat / cymbal distortion gate: receiver-side HF SINAD + crest + 15-23 kHz spill per chain variant (field chain, every Format Profile, per-stage isolation)
swift run --package-path macOS MPXPrime --verify-stereo-guard --seconds 4  # composite clipper stereo-guard share sweep (0..1): clipper / final-limiter duty, separation, M/S balance, HF SINAD -- where `mpx_clipper_stereo_guard`'s default comes from
swift run --package-path macOS MPXPrime --verify-final-ride --seconds 3  # Final-MPX limiter duty attribution: one composite-clipper candidate off per row (guards, OS factor, knee, look-ahead, limiter, shaper) on a hot chain and Music - Loud
macOS/.build/release/MPXPrime --verify-program-ab "$MPXPRIME_MUSIC_DIR" --seconds 30  # real-music A/B (AGC+multiband vs Advanced Dynamics) on a directory of captured audio files: Meter-engine BS.412/deviation/exceedance + decoded crest/image/band/pumping deltas; macOS-only (AVFoundation decode), release build (192 kHz renders); --ab-profile <id>, --ab-csv <path>
scripts/capture-program.sh --seconds 60 --name darkness  # record program audio from BlackHole 2ch into the $MPXPRIME_MUSIC_DIR corpus for --verify-program-ab (compiles scripts/CaptureToWav.swift on demand; watchdogs the AVAudioEngine silent-first-start bug)
./ab-music-live.sh --cycles 4 --window 30 [--soak <hours>]  # LIVE real-music A/B on TWO BlackHole devices (player -> 2ch input at 48 kHz, composite -> 16ch output at 192 kHz; NOT while Studio is on air): headless engine + REST, alternates advanced_dynamics_enabled per window while YOU play music, 2 Hz meters CSV; asserts zero xruns/ring overflows, Safety Clip idle, never over budget, deviation sane, every toggle applied live without a spike, uptime monotonic; --soak adds an RSS-growth bound. Exit 0 = pass.
macOS/.build/release/MPXPrime --bench-blocks  # block (buffer) size sweep on a RELEASE build: worst-block cost vs block duration, I/O latency, bit-identity across sizes, default output device HAL buffer range (~20 s)
./smoke-live.sh [--ini <path>] [--device-uid BlackHole2ch_UID]  # LIVE CoreAudio smoke on a virtual output (needs BlackHole 2ch at 192 kHz; NOT while Studio is on air): headless engine + REST, checks device start, tone deviation vs the Test Tone card's expected value, pilot %, Safety Clip 0, xruns, a live PATCH (deviation trace must follow within ~1 s), a restart-class PATCH + transport restart. Exit 0 = pass. ~70 s.
./calibrate-tx.sh --freq <MHz> [--watch|--dry-run|--tone]  # closed-loop TX deviation calibration against an off-air RTL-SDR measurement: reads the configured pilot injection over the REST API, measures actual pilot deviation (auto RF gain find, refuses railed captures, explicit 200 kHz channel filter via tuner mpx-offline), trims output_gain_db until they agree; attenuation-only respected ("raise exciter drive by N dB" when full scale under-deviates). Needs Studio running with the control API + the dongle receiving the TX.

# Baseline capture + strict compare
swift run --package-path macOS MPXPrime --capture-baseline      # writes macOS/verifier_baselines/default.json
swift run --package-path macOS MPXPrime --verify --baseline-strict

# Tests — MUST override DEVELOPER_DIR; CLT ships no Testing.framework, Xcode does.
# (Linux: plain `swift test --package-path macOS` — the toolchain ships Testing.)
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer swift test --package-path macOS

# Single test / filter
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer swift test --package-path macOS --filter BassClipperTests

# Release bundle + DMG
./build-release.sh 0.40

# Optional deep DSP combination test suite (~3 min; opt-in)
MPXPRIME_DEEP=1 DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer \
  swift test --package-path macOS --filter Deep
```

**Debug builds are not real-time capable.** `swift build` / `swift run` produce a debug binary without optimizer pass; the meter / scope / spectrum work in `refreshMonitoringSnapshot` runs slow enough to preempt the audio thread on a debug build, producing clicks, buffer underruns, or input-ring overflows. Use debug for development, unit tests, and `--verify` (which doesn't touch real audio devices). For any test that involves live audio I/O — bug-reproducing on real hardware, listening tests, regression checks of the actual chain — build release first: `swift build --package-path macOS -c release` and run `macOS/.build/release/MPXPrime`, or use the `./build-release.sh` DMG. If a user reports buffer issues, ask whether they're on a debug or release build before chasing a DSP regression. If buffer issues persist on a release build, check that Audio MIDI Setup's device format matches the configured `sample_rate` in the INI — CoreAudio's implicit SRC will starve the render thread on a mismatch, producing input-ring overflows and silent output that look identical to a DSP fault.

A deliberate DSP change that moves composite output recaptures all FOUR baselines in the same commit (`default`, `presets`, `long`, `receiver`, each platform-suffixed). Listening confirmation uses `docs/test-playlist.md` (sourced reference tracks per stage) on a release build.

Verifier exit codes: `0` = PASS, `1` = TIGHT (near limits, review), `2` = WARN, `3` = FAIL (post-injection composite overshoot -- the subcarrier budget was violated after pilot/RDS injection; checked first so a coinciding TIGHT finding can never mask it).

The `--verify --baseline-strict` baseline is schema 3 (`VerifierBaseline.swift`): besides the per-scenario composite metrics it pins a 4x-oversampled true-peak inter-sample-overshoot field and a global encoder-side sideband fingerprint (asymmetry + side/mono delta at 1/10/14 kHz). A DSP change that moves composite output requires recapturing via `--capture-baseline`. Since 0.45 the preset sweep and the long-run sweep pin their own baselines in the same schema (platform-suffixed `presets.json` / `long.json`; records keyed `<presetID>/<scenario>` for presets): capture with `--verify-presets --capture-baseline --seconds 5` and `--verify-long --capture-baseline --seconds 30`, compare on every run (drift = TIGHT, or WARN with `--baseline-strict`). A deliberate chain change now recaptures all three composite baselines in the same commit. `SampleINIDefaultDriftTests` additionally lints `macOS/MPXPrime.ini` against `AppConfig()` defaults -- a sample-vs-code difference must be whitelisted there with a reason.

Tests use **Swift Testing** (`import Testing`, `@Test` / `#expect`) — not XCTest. Do not add XCTest-based tests.

The default `swift test` is fast (~40 s; latest observed suite is 626 tests / 96 suites) and runs on every change. Timing-based tests (`DSPThroughputTests`) flake under contention; since 0.50 every relative-cost comparison there goes through `measurePair`, which re-measures both sides ONCE when the comparison fails (a preempted render on a shared CI runner is the usual cause; a real regression fails twice) -- if one still fails, re-run it alone before investigating. Test files that touch CoreAudio-only types (`AudioDevices`, `AudioDeviceListing`, the view model) must be wrapped in `#if os(macOS)` or the Linux test target does not compile. The optional deep suite (`DeepDSPTests.swift`, gated by `MPXPRIME_DEEP=1`) covers stage-interaction bugs: per-stage isolation, 50 random configs × 4 adversarial programs, pairwise enable/disable matrix, counteract pair detection, per-preset safety. Run on demand before a release or when touching multiple stages.

For DSP differences, prefer measurement-first validation wherever technically possible before asking the operator to listen. If a behavior can be characterized with deterministic signals, FFT/band-energy analysis, receiver decode metrics, alias/IM checks, peak/ceiling checks, stereo-link checks, CPU budget tests, or verifier/baseline comparisons, add or run those tests first. Listening tests are still useful for final subjective confirmation, but they should not be the primary regression detector for measurable DSP behavior.

## Architecture

### Layout

Runtime code is split across eight SPM targets on macOS (see the target list under "Project" above): the `MPXPrime` encoder executable, the `MPXPrimeMeter` analyzer executable, the shared `MPXPrimeCore` (DSP + `MPXDecoder` + `RDSStreamDecoder` + the Meter measurement engine) and `MPXPrimeUI` (Canvas components) libraries, `MPXPrimeNative` (FTZ/DAZ C shim), `MPXPrimeAcceleration` (Accelerate/os shim -- empty on macOS, SIMD vDSP/vvtanhf + lock polyfill on Linux), `MPXPrimeRecording` (WAV writer/recorder), and `CMPXTuner` (vendored RTL-SDR/SDRplay tuner). The Linux build swaps the macOS-only targets (`MPXPrimeMeter`, `MPXPrimeUI`, `CMPXTuner`) for `CAlsa` (libasound system library). Key files:

- `macOS/Sources/MPXPrime/` — the encoder executable target
  - `main.swift` — CLI entry, arg parsing, verify-mode dispatch
  - `AppConfig.swift` — INI-backed config model + live-apply routing (`RuntimeConfig`, `RDSRuntimeConfig`)
  - `INIParser.swift`, `AudioDevices.swift` — file and CoreAudio plumbing
  - `AudioOutputEngine.swift` — AVAudioEngine lifecycle, input tap, render callback
  - `ALSAAudioEngine.swift` — Linux CLI counterpart (ALSA capture/playback, `#if os(Linux)`); `MPXPrimeAcceleration` (Sources/MPXPrimeAcceleration/) holds the Accelerate/os shim, `CAlsa` (Sources/CAlsa/) the libasound modulemap
  - `Control/` — the remote-control plane (both platforms, default off): `ConfigPatch.swift` (INI-key PATCH engine; dispositions DERIVED by diffing `MPXGenerator.makeRuntimeConfig`/`RDSRuntimeConfig.make` between old/new configs — never add a per-key disposition table), `ControlBackend.swift` (protocol + DTOs), `HeadlessControlBackend.swift` (actor owning config+engine for --nogui; engine conformances), `GUIControlBackend.swift` (MainActor VM adapter), `ControlServer.swift` (Hummingbird routes + API-key middleware; loopback open, remote bind requires key), `PresetCatalog.swift` (ALL preset tables shared GUI/API — primebass/multiband/finalstage/format_profile; the GUI's apply* methods wrap it; both backends serve every kind), `SnapshotStore.swift` (the 8 preset slots' JSON sidecar), `DeviceCalibrationStore.swift` (0.50: per-device level-calibration memory — `<config>.devicecal.json` sidecar; input gain per input device, output level + line output per output device PER OPERATING MODE, name-fallback for USB UID drift; write-through on every persist, recall only on an effective device/mode change and never live-applied — the old rig is on air until the restart; both backends inject device enumeration so tests stay HAL-free), `InstallationKeys.swift` (0.50: `installationPreservedKeysBySection` + `applyingSnapshot` — snapshot LOAD preserves devices/engine format/mode/calibration/control keys from the live config in BOTH backends; save/export stay full-config), `WebUI/index.html` (embedded dashboard, SPM resource) + `WebUI/schema.json` (the dashboard's control schema — widget definitions + page model, served at `GET /api/schema`; index.html holds NO hardcoded control tables). **When adding an INI key, make a schema decision in the same change**: add a widget entry to schema.json, or add the key to `ControlSchemaTests.deliberatelyUnexposed` with a reason — the test fails otherwise, in both directions (unknown keys in the schema also fail). API config vocabulary IS the INI key set; `AppConfig` is `Equatable` for the change detector and `save(toINI:)` must round-trip every read key (sample_rate once didn't — keep load/save symmetric).
  - `MPXGenerator.swift` (~4400 lines) — the `MPXGenerator` engine class only: chain wiring, `RuntimeConfig`, live-apply, telemetry, `processAudioDomain` / `processMPXDomain` / `processFinalComposite`. Since 0.45 the stages live in `DSP/` (one file per concern, split out as pure moves): `DSPSupport.swift` (shared helpers `clampf`/`lerpf`/`zapDenorm`, oscillators, one-poles, LR4, `Lagrange4Interp`, envelope/K-weighting), `PeakLimiters.swift` (`OversampledPeakLimiter`, `StereoLinkedOversampledPeakLimiter`, `PreEncodeAudioLimiter`, `LookaheadLimiter`), `ToneShaping.swift` (phase rotator, parametric EQ, `PreemphasisFilter`), `Dynamics.swift` (`BandLimiter`, `DownwardExpander`, `WidebandAGCRider`, `MonoCompressor`, `AdvancedDynamicsLeveler`), `AudioClippers.swift` (`BassClipper`, `HFClipper`, `HFLimiter`, `DistortionCancelledClipper`), `CompositeClipper.swift` (`CompositeClipper`, `BS412PowerLimiter`), `LinearPhaseFIR.swift` (Kaiser-sinc design, FIR lowpass/decimator/interpolator/splitters), `SSBStereoEncoder.swift`; the RDS encoder is `RDS/BasicRDSCoder.swift`. New stages get their own file in `DSP/`; do not grow `MPXGenerator.swift`
  - `MPXDecoder.swift` (0.27, in `MPXPrimeCore`) — reusable FM stereo demod (pilot PLL, deemphasis, noise gate, stereo-collapse cooldown). Hot `process()` is `@inlinable`. Used by the monitor path with the delay-aligned reference and by `--verify-receiver` with a PLL-recovered reference. Sanitizes non-finite inputs (0.36) — one NaN/Inf sample used to permanently poison the pilot-lock I/Q + envelope state (smoothers never flush NaN, self-heal can't re-arm); keep the `isFinite` guard at the top of `process()`. 0.45: the lock-in phase correction is closed into a second-order PLL (~2 Hz, critically damped) so a pilot FREQUENCY offset no longer caps separation (measured 24.8 dB at 100 ppm before, 64.4 dB after; on-frequency unchanged, `receiver.json` did not move), the pilot-lock gate is LEVEL-RELATIVE (~2.5% of the composite mean square; the old absolute gate silently decoded mono over a 20 dB window while PILOT read present), `stereoDecodeActive` publishes the decode state up to the Meter's "MONO DECODE" badge (which blanks separation / balance / correlation), and a sub-Nyquist rate decodes exact mono instead of aliases. `MeterDecodeIntegrityTests` pins all of it -- do not revert the loop to a fixed-lag lock-in or the gate to an absolute magnitude.
  - `MeterAnalysis.swift` / `MeteringPrimitives.swift` (in `MPXPrimeCore`) — the Meter's measurement engine (see the measurement-semantics note under "Project" above). Covered by `MeterAnalysisTests`.
  - Meter GUI (`macOS/Sources/MPXPrimeMeter/`): `RootMeterView.swift` (dashboard), `MeterViewModel.swift` (+ `MeterTelemetry` isolated observable), `MeterAudioEngine.swift`, `SDRLibraryInputSource.swift` (in-process RTL-SDR/SDRplay via `CMPXTuner`), `MeterAppDelegate.swift`.   - `BandLimitedStep.swift` (0.27) — BLEP/BLAMP correction primitive for the US 6,937,912 anti-aliased clipping work
  - `AcceleratedBandlimitedResidualClipper.swift` (0.27) — vDSP-accelerated patent-style residual-bandlimiting clipper, opt-in via `pre_encode_bandlimited_residual_enabled`
  - `StereoInputRingBuffer.swift` — lock-free input → render bridge
  - GUI (macOS-only, each file wrapped in `#if os(macOS)`), split in 0.45 from the former single `SwiftUIControlApp.swift`: `MPXPrimeViewModel.swift` (the `@MainActor` view model, ~3200 lines), `AppDelegate.swift` (windows, menus, aux-window lifecycle), and `UI/` -- `AppConstants.swift` (window sizes/titles/URLs, app icon), `NavigationModel.swift` (`AppSection` / `ProcessingTab` / `RDSTab` / `Stage` enums, monitoring health types), `RootViews.swift` (split view, sidebar, `Card`), `SnapshotsAndTestTone.swift`, `MonitoringDashboard.swift` (dashboard, meters, spectra, `TabHelpBox`), `AudioIOTab.swift` (0.50: the Audio I/O sidebar section — device pickers, the segmented Operating Mode over the two stored booleans, per-device level calibration incl. the DAC Peak readout, engine format; calibration deliberately does NOT live on the DSP tabs and per-tab resets never touch it), `ProcessingTabs.swift` (one `Processing*Tab` view per stage), `SettingsAndRDSTabs.swift` (RDS tabs + the slimmed Settings window: config path, spectrum window, remote control), `HelpAndAbout.swift`, `SharedControls.swift` (`DoubleSliderRow`, `IntStepperRow`, `RestartBadge`, detached scope/spectrum views). ### Signal chain (critical invariants)

The audio path runs ~24 stages, ending with **post-clipper pilot + RDS injection**. Anything that touches the chain order needs to preserve two non-obvious invariants:

1. **Subcarriers (19 kHz pilot, 57 kHz RDS) MUST be injected after all peak-control stages.** They bypass the composite clipper, BS.412, and final-MPX safety limiter. Constant-amplitude subcarriers are required for reliable stereo decoding and RDS reception — this matches professional broadcast practice (Omnia, Orban, Stereotool). The clipper has explicit pilot-guard (17–21 kHz) and RDS-guard (55–59 kHz) cancellation — clipping IM in those bands is removed before subcarrier injection so the receiver doesn't see clipper noise vector-summed with the cleanly-injected pilot/RDS.
2. **Pre-emphasis runs in L/R domain immediately upstream of the pre-encode limiter** (canonical Optimod / Stereotool placement; relocated post-0.24). The network is `PreemphasisDesign` (MPXPrimeCore): a minimum-phase biquad least-squares-fitted to the ANALOG curve `|1 + j omega tau|` at configure time (<0.05 dB to 15.5 kHz at 48 kHz; matched-z fallback), and the decoder's `DeemphasisFilter` is its exact inverse. Do not "simplify" either back to the textbook matched-z first-order network: at the 48 kHz audio domain it under-boosts by 0.6 dB at 10 kHz / 1.4 dB at 15 kHz, and real receivers de-emphasise with the analog curve (`PreemphasisFilterTests` pin both against it). The limiter peak-controls the +10..12 dB HF-boosted signal before composite assembly. The pre-2026 M/S placement and the b806053 cost-regression history that originally motivated it are recorded in plan.md "Pre-emphasis placement (history)"; the b806053 regression class is no longer reproducible on the current chain.
3. **Stereo polarity is the standard one and the decoder has NO sign compensation.** `makeCompositeComponents` sends `S = (L - R)/2` on `sin(2*theta)` with the pilot `sin(theta)` (47 CFR 73.322 / BS.450-3: positive-slope subcarrier zero crossings at the pilot zero crossings; a receiver forms `L = M + S`). `MPXDecoder` (monitor path, Meter, verifier) is a plain textbook decoder. Pre-0.45 the encoder sent `(R - L)/2` and the decoder negated it back, so every in-repo gate was self-consistent while real receivers swapped L/R. `StereoPolarityTests` pin both sides against an independent decode, and `--verify-receiver` scores separation against the DRIVEN channel (`drivenChannelSeparation`) -- never reintroduce "stronger vs weaker" scoring, it hides exactly this fault.

Peak control:
- **HF limiter** (0.45, `HFLimiter`, `hf_limiter_*`, default ON in every profile) -- program-controlled pre-emphasis (Orban US 4,103,243, expired): between pre-emphasis and the pre-encode limiter, rides only the boost component `pre - flat` (`out = flat + g * boost`), stereo-linked feed-forward detector with a boost-dominance guard (boost >= 20% of the peak, else the peak is left to the broadband limiter), 1.5 ms / 5 ms hold / 20 ms. It replaced the HF *clipper* in Music - Loud: the clipper is a waveshaper on the cymbal band and cost 17 dB of decoded HF SINAD on hats. Runs at the audio-domain rate (`audioDomainSampleRate`) -- the HF clipper's live-apply used to reconfigure at the MPX rate, fixed 0.45. Do NOT remove `processEncoderHFGuard` as "redundant" with it: measured 2026-08-29, removing the guard cost 20-40 dB of receiver-side HF stereo separation on the tone test (un-attenuated HF drives the composite clipper into audio-band IM) while this limiter did not engage at those levels. The 19 kHz audio-path notch and the experimental multiband composite clipper WERE removed in 0.45 (notch: receiver gate identical to 0.01 dB; MB clipper: its A/B gate went TIGHT in both possible positions).
- **Final-stage order + budget reference (0.45, load-bearing).** `processFinalComposite` runs composite clipper -> 55 kHz bandwidth FIR -> BS.412 -> final look-ahead MPX limiter -> experimental multiband clipper -> shaper (`softClipSafety`) -> budget governor -> pilot/RDS injection. The clipper's configured CEILING is normalised onto the audio-composite budget (`thresholds.preLimiterCeiling`) and the limiter's threshold onto the budget itself, per sample (0.985 x budget until the A1b fix: the old instantaneous-|x| detector leaked ~1-3 dB of dense program past its threshold into the 1x shaper and under-reported its GR by the same amount; `LookaheadLimiter` now uses a `SlidingWindowMax` over the delay line plus a gain floor, `LookaheadLimiterTests` pin "nothing above the threshold leaves", and `--verify-final-ride` prints every peak controller's duty). Do NOT move the shaper ahead of the clipper or read clipper/limiter thresholds against full scale again: until 0.45 that combination meant the 1x guard-less shaper did ALL the clipping in every profile and the oversampled clipper + limiter never engaged (`--verify-hf-transients`: clipper on/off bit-identical; shaper cost ~13 dB of decoded HF SINAD on hats). The clipper's guard-band restoration leaves in-band overshoot by design (`CompositeClipperBoundProbeTests`: 1.18 vs 0.966 ceiling on a 12 dB overdrive), so the limiter's ~1 dB duty on `bright_dense` (Music - Loud; 2.6 dB on the hot Verification.ini config) is normal (verifier TIGHT > 3 dB, WARN > 4 dB) and `CompositeShaperOrderingTests` pins the shaper idle (< -40 dB relative action) behind clipper + limiter -- the `SAFETY CLIP` telemetry reads 0.0 on dense program since A1b.
- **Pre-encode audio limiter** — L/R, stereo-linked, after pre-emphasis, before stereo encoding. Uses `StereoLinkedOversampledPeakLimiter` (4× oversampled true-peak with tanh ceiling, shared gain envelope from `max(|L|, |R|)`; since 0.45 its 4:1 decimator is a `LinearPhaseFIRDecimator` flat to 15 kHz and 80 dB down from 16.5 kHz at the 48 kHz audio domain -- it doubles as the chain's 15 kHz band-limit in the pre-emphasised domain, because the encoder FIR runs BEFORE pre-emphasis and its transition tail arrives +14 dB hotter. The 6th-order Butterworth at 0.30 x fs it replaced cost -2.3 dB at 14 kHz on air. Do not lower its passband or widen its transition without re-running `DualRateHFResponseTests.productionChainFollowsTheAnalogPreemphasisCurve` and the `--verify-hf-transients` gap-spill column together -- they pull in opposite directions). Live-apply must configure it at `audioDomainSampleRate` (`liveApplyKeepsTheAudioDomainRate`). 0.30: default-on look-ahead (`pre_encode_lookahead_ms = 1.0`, audio-rate delay + un-delayed `futurePeak` detector into `stereoStep`, US 4,208,548 prior art) and default-on Dolby HF-subband-aware detector (`pre_encode_lookahead_hf_only = True`, `pre_encode_lookahead_hf_cutoff_hz = 4000`, US 5,579,404 / EP 0685130, expired 2013) — detector path high-passes input so look-ahead engages only on HF transients where pre-emphasis concentrates peaks; audio path stays full-band. Look-ahead settings are restart-required (allocate delay buffer / reconfigure detector biquad).
- **Composite clipper** — 16× oversampled tanh soft-clipper on the audio composite, **differential topology** (only the clipping residual goes through decimation; wanted signal rides a 1× delay-matched bypass), with delta-based per-band substitution that protects audio (0–17 kHz, opt-in), pilot guard (17–21 kHz), stereo subcarrier (22–53 kHz, a 0...1 SHARE since 0.45: `mpx_clipper_stereo_guard`, replaced the `mpx_clipper_cancel_stereo` toggle -- at 1 the clipper only clips the mono share of an M+S peak and the final limiter rides the overshoot, at 0 it clips the full composite like Orban / Omnia / Stereo Tool; the default is picked from `--verify-stereo-guard`, never by taste), and RDS guard (55–59 kHz) bands. Decimation via `LinearPhaseFIRDecimator` (Kaiser-windowed sinc, auto-sized to OS rate, `vDSP_dotpr` polyphase, ≥90 dB stopband). Replaces the old `CompositeTruePeakLimiter` (deleted in 0.11) which used `|composite|` peak detection + memoryless tanh and produced intermod that demodulated as `(L-R)` cancellation. Inspired by Orban US 4,460,871 + US 5,737,434 (delta-cancellation primitive, expired) and US 6,337,999 (differential topology, expired 2022 — landed in 0.20).

`Mono Mode` suppresses pilot, stereo subcarrier, and RDS — true mono composite.

The built-in **test tone is a calibration source** (0.45): while a tone sample renders, `renderingCalibrationTone` bypasses input gain and every gain-changing stage, replaces Final Drive by the audio-composite budget (0 dBFS = 100% audio modulation) and makes the clipper/limiter transparent while keeping their delay; sines are pre-emphasis-compensated. Do not route the tone through the processing again -- `TestToneGeneratorTests` pins level-in / deviation-out.

Oversampled clippers: `BassClipper` 4× and `DistortionCancelledClipper` 8× share a `Lagrange4Interp` + `BiquadCascade6` decimation pattern (12th-order Butterworth LP). `CompositeClipper` runs at the `mpx_clipper_oversampling` rate (default 16×, operator-selectable across {8, 16, 32} since 0.30; restart-required) with `Lagrange4Interp` + `LinearPhaseFIRDecimator` (Kaiser-windowed sinc, `vDSP_dotpr` polyphase) — linear phase and tighter stopband than the Butterworth cascade, at the cost of group-delay latency folded into `subcarrierDelayLine`. Per-host batch buffers default-size to 32 elements (the supported max) so swapping between factors is non-allocating after first `configure()`. Soft-clip `tanhf` calls in all three are batched through `vvtanhf` (vForce SIMD) for ~5–9× speedup vs scalar tanhf at 8/16-element batches — see `TanhBatchSizeBench` for the curve. Follow these patterns for any new oversampled nonlinearity.

`MPXGenerator` seeds `useEncoderFIR` / `useMultibandFIR` from the config flags at construction (TX filters by default), and only the monitor output mode switches them off via `setEncoderFIREnabled` / `setMultibandFIREnabled` in `AudioOutputEngine`. Do not go back to "off until the engine enables them": until 0.45 that left every `--verify*` gate, every baseline and the Linux ALSA engine on the IIR monitor filters without anyone noticing.

The multiband compressor has two crossover backends, picked at engine start by output mode:
- **TX path** uses `LinearPhaseMultibandSplitter5` / `3` — Kaiser-windowed-sinc FIR splitters with parallel-cumulative-LP topology, all bands sharing group delay so summed bands reconstruct the input delayed-by-`groupDelaySamples` exactly (sum-to-flat at –155 dB). Eliminates IIR-LR4's transient smear and inter-band pumping. The splitter OWNS the crossover design (0.45): per-crossover transition = fc floored at 120 Hz, -6 dB exactly at the crossover (the Kaiser kernel is designed at fc - transition/2), 40 dB stopband, kernels zero-padded to the longest so all bands share one group delay -- 446 samples = 9.3 ms at the 48 kHz audio domain with the default 90 Hz lowest crossover (`MultibandFIRSplitterTests` pin the -6 dB points, the < 12 ms budget, the pre-ringing bound and sum-to-flat). Before 0.45 it ignored the caller's transition, used 60 Hz everywhere, sat on the 2049-tap clamp (21.3 ms) and pre-rang ~12 ms at the upper crossovers; do not reintroduce a shared narrow transition. Convolution runs through `vDSP_dotpr` (double-buffered delay line) — without that the FIR path overruns real-time budget on most machines (manifests as audio crackle + RDS BCH corruption from sample dropouts).
- **Monitor path** keeps the IIR `StereoLinkwitzRiley4` chain for low latency.

The multiband bands' `multiband_release_program_dependent` (default on) is a real dual-slope release since 0.45 (`MonoCompressor`: GR-domain smoother, ~1.5 s platform of the DEMANDED reduction, fast below the platform / 3x slower above it, detector release shortened to <= 30 ms so it does not add a second pole) -- before 0.45 the flag multiplied the release time by a constant 1.1. `MultibandReleaseShapeTests` pin kick recovery, level-drop gentleness and the flag-off path. Do not average the APPLIED gain for the platform: it feeds back and freezes the band at kick depth (measured).

Multiband Phase 2 is implemented but opt-in: `multiband_transient_aware_attack_enabled = false` by default. When enabled, `MonoCompressor` uses an RMS/peak hybrid detector and briefly stretches attack on peak-vs-RMS transients so percussive fronts pass hotter while sustained material settles near the classic peak-detector level. Keep it verifier-backed before enabling it in presets.

Multiband inter-band coupling is implemented but opt-in: `multiband_inter_band_coupling_enabled = false` by default. When enabled, low-band gain reduction is smoothed (20 ms attack / 300 ms release) and gently biases upper-band thresholds lower so bass-heavy passages keep tonal glue without wideband pumping. Keep it preset-gated until program-material A/B confirms the balance.

SSB Stereo is implemented but opt-in: `mpx_ssb_stereo_enabled = false` by default. When enabled the stereo encoder leans the 38 kHz L-R subcarrier toward single-sideband (`SSBStereoEncoder`: linear-phase Hilbert FIR + matched program delay + opportunistic lower-peak sideband selection with hysteresis; both subcarrier phases from the pilot recurrence via `sin2x`/`cos2x`). Decode-compatible and mono-transparent (test-pinned); `--verify-ssb-stereo` is the hard gate (sideband asymmetry vs theory, coherent separation, budget). The measured headroom reclaim on synthetic scenarios is currently ~0 -- the gate deliberately reports TIGHT until dense real-program A/B demonstrates the benefit; the follow-up direction is sideband choice inside the composite clipper loop. Keep it preset-gated.

Advanced Dynamics is implemented but opt-in: `advanced_dynamics_enabled = false` by default. When enabled it REPLACES the wideband AGC and the multiband compressor with one fused 5-band leveling stage (`AdvancedDynamicsLeveler`) -- target-based configuration (target/offsets/density/speed keys `advanced_dynamics_*`), program-adaptive time constants (transient-accelerated attack via precomputed coefficient anchors, freeze-at-target hold, density-slowed release), own lazy-allocated FIR splitter at the multiband crossovers, all live-apply. When off, the chain is bit-identical (the AGC gate is `widebandAGCEnabled && !advancedDynamicsEnabled`). `--verify-advanced-dynamics` is the A/B gate (also measures re-processing idempotency and cost vs the two replaced stages); keep it preset-gated until program-material A/B plus listening confirm it.

RDS baseband uses EN 50067 biphase shaping and a pilot-locked subcarrier. The 57 kHz carrier is derived from the pilot oscillator's recurrence (`pilotOsc.s`) via the triple-angle identity (`3s - 4s^3`), passed into `BasicRDSCoder.updateRDSPilotSin` per sample — NOT a separate additive phase accumulator. The old accumulator path drifted ~9 deg / 5 s against the emitted pilot (it added `Float(w)` while the broadcast pilot / 38 kHz subcarrier ride the s/c recurrence); fixed 0.36, gated by the pilot/RDS phase-lock drift check in `--verify-receiver`. Do not regress the production path to a free-running 57 kHz oscillator. RDS carrier frequency is config-only; the UI exposes carrier level and program data.

### Configuration + live-apply

`AppConfig` maps INI keys to runtime settings. Most DSP params and **every operationally-toggled RDS setting** are live-apply (no engine restart); a few are restart-only. When adding a setting, classify it explicitly via `runtimeDisposition:`.

Three live-apply dispositions:

- `.live` — DSP-domain setting. Routes through `applyLiveRuntimeConfigIfRunning` → `RuntimeConfig` → audio thread.
- `.liveRDS` — RDS-domain setting. Routes through `applyLiveRDSConfigIfRunning` → `RDSRuntimeConfig` → `BasicRDSCoder.applyRDSRuntimeConfig`. The `RDSRuntimeConfig.make(from: AppConfig)` factory is the canonical AppConfig->runtime mapping (engine builder + test suite both call it) -- but `BasicRDSCoder.init(config:)` is a separate hand-written duplicate of it, so two things keep them honest: every engine start (headless backend AND GUI) re-applies both runtime planes to the fresh engine right after `start()` (restart-equals-live by construction -- do not remove those calls), and `RDSRestartParityTests` pins init vs make()+apply bit-for-bit. When adding an RDS runtime field, add it to BOTH mappings and to the parity test's `richConfig()`.
- `.restart` — requires transport stop/start. Use this for physical-layer settings that reconfigure the modulator FIR / oversampler / sample-rate plumbing.
- `.none` — handled via a side channel (e.g. now-playing script reload), no runtime apply needed.

RDS settings that stay restart-only: `rds_level` (injection kHz), `rds_gaussian_*` (FIR taps + BW). Everything else — master enable, PI, PTY, PTYN, ECC, LIC, TP/TA/MS/DI, AF list/method, group sequence, scheduler, CT/ID/TZ, all RT/PS/Long PS text — applies live. The 57 kHz subcarrier frequency is spec-fixed (EN 50067 Sec 2.1.4, locked to 3x pilot) and is not user-configurable.

When toggling `rds_ta` live, `BasicRDSCoder.applyRDSRuntimeConfig` sets `forceNextGroupForTAEdge`. The next `nextGroupBits()` call honours it by emitting a forced 0A ahead of the schedule (UECP §2.5.1.1). CT (4A, minute-aligned) keeps higher priority than the TA-edge force flag.

**Block size** (`blocksize`, `[INTERFACES]`, 256..8192, GUI picker + dashboard): the DSP is block-invariant by construction (`BlockSizeInvarianceTests`: 64 / 480 / 1024 / 4096 / 8192-frame renders are bit-identical to 512), so the size is purely a latency-vs-safety knob; `--bench-blocks` measures it (M1 Pro, 192 kHz, full chain: worst single block 17% of its duration at 512, 23% at 256, 46% at 64). The RDS text scheduler paces PS/RT by wall-clock uptime, so any bit-identity comparison of two offline renders must run with RDS off. CoreAudio devices clamp the HAL buffer to their own range (the engine logs a routing note); the built-in output tops out at 4096.

`AppConfig.load` resets a pre-0.45 INI (legacy `format_profile_id`) to the migrated Format Profile: `[MPX]` rebuilt from defaults + profile except `legacyResetPreservedMPXKeys` (calibration), `[RDS]` / `[INTERFACES]` / `[CONTROL]` kept verbatim; both runtimes save the result and announce it (`loadReportingMigration`, `LegacyINIResetTests`). Adding a calibration-class key to `[MPX]` means adding it to that list.

Verification.ini key name collisions are a known sharp edge — when adding a setting, grep `AppConfig.swift` for the exact config-key string before naming a new one. The composite clipper itself uses `mpx_clipper_*` keys; the legacy `composite_clipper_enabled` key (which used to control the now-removed composite limiter) was deleted in 0.11.

### Threading

- **Audio render callback**: real-time thread. Lock-free, allocation-free. No blocking I/O, no dispatch, no `Task { ... }`, no string formatting, no `NSRegularExpression` compilation. Cache compiled regex as `static let`. **Use `BasicRDSCoder.monotonicSeconds()` (`ProcessInfo.systemUptime`, commpage-backed) for elapsed-time math, not `Date()`** — the only `Date()` calls retained on a render-reachable path are the RT `{time}/{date}` macro substitution (justified — needs wall clock) and the CT cache refresh (runs on background queue). New code must follow the same pattern.
- **Main thread**: SwiftUI UI. For timer callbacks into `@MainActor` state, use `MainActor.assumeIsolated {}`, **not** `Task { @MainActor in ... }` — the latter heap-allocates and accumulates pressure on long-running meters.
- **Background metering**: `.userInteractive` QoS dispatch queue. Skip calculations when `meteringEnabled` is false (UI not visible).
- **RDS clock cache**: `clockUpdateQueue` (utility QoS) refreshes the atomic CT cache once per second. `enCT` / `enID` toggling on at runtime calls `startClockCacheIfNeeded()` to prime + start the timer if it isn't already running (idempotent).

Hot-path optimization: prefer `vDSP_*` (Accelerate) over Swift loops. Pre-allocate buffers at engine start. Use `@inline(__always)` on tiny hot helpers. CPU profiling: use Instruments (Time Profiler).

Concrete vDSP wins already in place:
- `vDSP_dotpr` for FIR convolution (encoder bandwidth FIR + multiband FIR splitters). 5–10× vs manual loop. Required for FIR multiband to fit real-time budget.
- `vvtanhf` (vForce) for batched soft-clip in `CompositeClipper`, `BassClipper`, `DistortionCancelledClipper`. Pre-compute oversampled inputs, batch the tanh, then run per-OS-step state-dependent work. ~5× at 8-element batches, ~9× at 16-element.
The structural pattern in both cases is the same: extract the parallelisable transcendental/dot-product work from inside the per-sample/per-OS-step loop, do it as a vector, then continue the recursive (biquad/delay-line) work sequentially.

## Conventions

- **ASCII only** in source and docs. No non-ASCII punctuation / symbols.
- **All automated tests run headless.** `swift test`, the `--verify*` gates, `--bench*` and `smoke-live.sh` must never open a window, touch a real audio device, enumerate CoreAudio for real, or need a logged-in GUI session. Tests that need a view model inject a device lister (`MPXPrimeViewModel(configPath:deviceLister:)`, see `ViewModelDeviceSourceTests`); DSP tests render through `MPXGenerator` directly; anything that needs a device uses a virtual one (BlackHole) and is opt-in. A test that pops a GUI or an "interface unavailable" dialog is a bug, not a flake -- it also cannot run in CI.
- **After ANY change, update ALL affected docs in the same change — always.** Docs are part of "done", like tests. Before calling a task done, ask which docs the change touches and update them together: `docs/ARCHITECTURE.md` (DSP chain / signal flow / stage behavior / output modes / RDS / verifier surface / targets), `docs/manual.md` (**Studio** user-facing behavior, UI labels/controls, config keys, presets, operator workflow) and `docs/manual-meter.md` (**Meter** input/readouts/recording/calibration — the manuals are split per app), `README.md` (product name, features, install, what ships in the DMG), `CHANGELOG.md` (an entry under the current Unreleased / version section), and **this file `AGENTS.md`** (project structure, targets, conventions). Edit `AGENTS.md` directly — `CLAUDE.md` is a symlink to it; never write through the symlink (a `perl -i` once replaced it with a regular file). Do not let docs drift behind the code: e.g. the 0.35 relabel renamed the composite-clipper guards `Cancel ...` -> `Protect ...` (UI + manual both), and MPX Prime Meter shipping in 0.37 needed README/manual/ARCHITECTURE coverage.
- **File layout is a maintainability contract (0.45 split).** The three former monoliths (`MPXGenerator.swift` 10.8k, `SwiftUIControlApp.swift` 9.1k, `VerificationHarness.swift` 4.4k lines) were split into `DSP/`, `RDS/`, `UI/`, `Verification/` by concern as pure moves (strict baselines unchanged). Keep it that way so a human can develop here without an AI: one type or one closely related family per file, files under ~1000 lines (the view model and `MPXGenerator` class are the tolerated exceptions and must not grow), folders by concern, `private` for anything used in one file and `internal` only for genuinely shared symbols, and a new stage / tab / verify mode gets a NEW file rather than an extension of an existing one. Structural cleanup of the final MPX chain itself is still done in small, verifier-backed steps -- **do not** opportunistically refactor `processFinalComposite`; even behavior-preserving edits can measurably move composite output.
- Device UIDs are platform-specific — always enumerate, never hardcode.
- New DSP stages ship **disabled by default** and must support live-apply via `RuntimeConfig` unless there is a specific reason not to.
- Avoid reintroducing separate Stereo/RDS menus; use unified navigation.
- **Unit tests never touch audio hardware.** `MPXPrimeViewModel(configPath:deviceLister:)` takes its device source by injection; every test that constructs a view model passes `deviceLister: { [] }` (or a stub list), pinned by `ViewModelDeviceSourceTests`. Never call `AudioDevices.list()` (CoreAudio HAL) from a test path, and never start an engine in a unit test -- `swift test` must stay headless and dialog-free.
- **Safety-clip duty telemetry** (`FinalLimiterStatus.safetyClipDB` -> `mpxSafetyClipDB` / ALSA `safetyClipDB` -> GUI "SAFETY CLIP" + `/api/telemetry.safetyClipDB`) reads 0.0 when clipper + final limiter own the peaks; keep it wired when touching the final stage -- it is the on-air detector for the 0.45 distortion class.
- **High-frequency monitoring UI must not invalidate the view model.** Meters, scopes, spectrum, and live numeric readouts update at the metering rate (up to 30 Hz). Four rules, all load-bearing (see CHANGELOG 0.34 — the multi-hour GUI freeze — and the Unreleased Meter lag/stutter fix):
  - **Draw moving graphics in `Canvas`, never as layout** — no SwiftUI subview whose `.frame(width:/height:)` or `.offset` tracks a live value. A value change must be a repaint, not an Auto Layout pass.
  - **Read live values from a dedicated per-tick observable, not `@Published` on the view model.** Per-tick values live on their own object (`LiveTelemetry` in Studio, `MeterTelemetry` in the Meter; the view model keeps one-line forwarding properties so writer code is unchanged); wrap live readouts in the isolation wrapper so a tick re-evaluates only those leaves. Putting per-tick state back on the view model recreates the window toolbar every tick (documented SwiftUI-on-macOS leak) and progressively freezes the GUI over hours. Detached high-refresh windows also set `NSHostingController.sizingOptions = []`. The 8 Hz "readout pulse" experiment was tried and reverted — don't reintroduce it.
  - **Per-tick observable state uses the `@Observable` macro, NOT `ObservableObject`/`@Published`.** Always prefer `@Observable` for any new observable state; for high-frequency telemetry it is mandatory. Profiling a long Meter SDR session showed the `ObservableObject` bridge's dependency tracking (ObservationRegistrar `AnyKeyPath`-set hashing) accumulating over the session — ~36% to ~87% process CPU in 14 minutes — degrading the GUI and starving the real-time audio thread; only a fresh launch cleared it (the view tree survives engine stop/start). `@Observable` tracks per-property, re-evaluates only leaves whose read values changed, and its tracking cost stays flat. Wrap with `LiveObservationView` (both apps' telemetry objects are `@Observable`; the legacy `LiveTelemetryView` ObservableObject wrapper was removed once Studio's `LiveTelemetry` migrated).
  - **Disable implicit animations on every live Canvas view** — `.transaction { $0.animation = nil }` (all `MPXPrimeUI` live views carry it; keep it on new ones). Without it, 25-30 Hz updates queue frame-interpolation transactions that add per-frame overhead.

If the disclaimer wording changes, edit README (and the About's one-liner only if that key phrase changes); never grow a second copy.
- **Control labels use outcome language; jargon lives in tooltips.** The target operator is broadcast/RF-literate but not a DSP engineer. KEEP established broadcast terms on labels (pre-emphasis, pilot, RDS, PTY/PI/ECC, deviation, composite clipper, BS.412, phase rotator, AGC, multiband). Do NOT put patent/topology/DSP-implementation phrasing on a label — say what the control does for the signal ("Protect Stereo Pilot", "Reduce Clipping Distortion", "Audio Clipper"), and push the mechanism (distortion-cancellation topology, LR4/Gaussian/FIR internals, Orban/US-patent references) into the `.help()` tooltip or the bottom help box. When two views control the same thing, use one vocabulary across both (the inspector matches the main tab). Collapse expert / set-once / experimental controls into a `DisclosureGroup` (reuse the Audio Limiter "Advanced" pattern) so common controls stay prominent.
- **Accessibility lint** — the project ships a `.swiftlint.yml` that runs only `accessibility_label_for_image` and `accessibility_trait_for_button` (no broader style enforcement; DSP code uses many intentional patterns that fight the default SwiftLint rule pack). Run with `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer swiftlint` from the project root before committing UI changes. Decorative SF Symbols (icons next to descriptive text, info-circle in help boxes) should use `.accessibilityHidden(true)`; icon-only buttons need `.accessibilityLabel(...)`.

## Release prep

- Bump version in `AppConfig.swift` (`appVersion`), `build-release.sh` (default), `README.md`, and `CHANGELOG.md`.
- `swift build --package-path macOS -c release` is clean.
- Manual smoke test with `--gui`: monitoring + processing tabs work.
- `./build-release.sh <version>` produces the universal binary + DMG under `macOS/dist/`. On Linux, `./build-deb.sh <version> [distro-label]` produces `mpxprime_<ver>_amd64.deb` (static Swift stdlib + systemd unit) after a `--static-swift-stdlib` release build; the release workflow (`.github/workflows/release.yml`) builds the macOS DMG plus the Ubuntu 24.04 deb on a `v*` tag (the 26.04 leg is removed until Swift.org ships a 26.04 toolchain; the static-stdlib 24.04 deb runs there anyway). Pushes to `develop/**` and PRs to `main` run `.github/workflows/ci.yml`: build + tests + swiftlint + the fast verify gates (incl. `--verify --baseline-strict`, per-platform baselines) on macOS and Ubuntu 24.04.
- Branch model: `main` is the default branch and tracks released versions. The integration branch is always named **`develop/v.NNN`** — three digits, leading zero — after the next target version (currently `develop/v.044`; 0.43 shipped 2026-08-01, and 0.44 is the Unreleased target accumulating on `develop/v.044`). Unreleased work accumulates there; feature work either commits directly on the integration branch or on short-lived branches off it. Releases ship by **squash-merging** the integration branch into `main` (one commit per shipped version, NOT `--ff-only`), tagging `v<version>` from `main`, and pushing the tag — which triggers `.github/workflows/release.yml`, runs `./build-release.sh <version>`, and publishes the resulting DMG as a GitHub Release. After a release ships, cut a new `develop/v.NNN` branch off `main` for the next target version. Tags themselves use `v<version>` without zero-padding (e.g., `v0.21`, `v0.28`); only branch names use the `v.NNN` form.
- **Release prep vs. tagging is split.** An agent prepares a release — version bump in the four files, CHANGELOG entry, commit + push to the integration branch — but does NOT merge to `main` or push the tag. The maintainer runs the hardware-dependent checklist items (live 192 kHz device smoke, RDS receiver smoke, VoiceOver pass) and pushes the `v<version>` tag, since those cannot be done from a headless agent and the tag push publishes a public DMG.
- Optionally run the deep DSP combination suite (`MPXPRIME_DEEP=1 swift test --filter Deep`, ~3 min) before tagging — catches stage-interaction regressions the default suite misses.

### Release validation checklist

Run before tagging. None of these should be skipped on a release commit; partial coverage is how regressions ship.

**Run the offline `--verify*` gates from the REPO ROOT** — they hard-fail (exit 64) if `macOS/Verification.ini` is not findable from the current directory, rather than silently verifying the operator's live station INI (which produces official-looking verdicts about the wrong config). **And run them on an otherwise-idle machine — quit the GUI app, and ideally browsers / media players too.** They are single-threaded CPU-bound renderers (no GUI, no audio devices — already headless). A running MPX Prime Studio GUI or other heavy apps starve them to ~20-37% of one core, so an 8-16 s gate can crawl to 20+ minutes and look hung when it is only contended. On an idle machine: `--verify` ~16 s, `--verify-presets` ~8 s. The slowness is contention, not a regression — don't chase it as one, and don't run the verify sweep next to a soak/listening instance.

- [ ] **Docs audit** — before tagging, verify ALL user/contributor docs match the code being released: `docs/manual.md` + `docs/manual-meter.md` (features, UI layout incl. the web dashboard's actual pages, endpoint table vs `ControlServer.swift` routes, config keys), `docs/ARCHITECTURE.md` (chain order, stage list, verifier-mode enumeration), `README.md` (feature claims per app, no promises about removed features), `docs/BUILDING.md` (CLI flags vs `main.swift`), CHANGELOG. Every Unreleased CHANGELOG bullet must have doc coverage; the 0.44 cycle showed per-commit doc discipline can still leak (two web-parity commits shipped no doc changes), so this checklist item is the backstop.
- [ ] `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer swift test --package-path macOS` — full default suite passes
- [ ] `swift build --package-path macOS -c release` — release build clean
- [ ] `DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer swiftlint` — 0 violations (accessibility lint)
- [ ] `swift run --package-path macOS MPXPrime --verify --seconds 5` — exit 0 (PASS)
